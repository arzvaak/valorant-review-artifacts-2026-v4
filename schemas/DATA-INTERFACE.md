# Schema-only data interface

`feature-layout.json` is the copied schema descriptor from the saved 2026-10-11 study package, SHA-256 `ad5455e54ea1a6ab9b8312846910d54d7d1ff43d6b53957c412eb1f0c0fcdcc7`. It enumerates feature names under map-winner and series-winner tasks. It contains no row values, identifiers, targets, or matrices. Some fields name performance families and are source-derived; external inclusion remains subject to the same rights review as the aggregate outputs.

The portable software snapshot expects a fully bootstrapped release root with its configuration, methods, environment identity, trained/staged data, and source registry. Its `core-original/README.md` gives the historical entrypoint as `bootstrap.py` followed by `run.py --root <root>`; the inspected bootstrap requires CUDA and writes a hardware/environment lock. The candidate has neither a compatible lawful row-level input root nor the exact model-training dependency/CUDA lock, so this command is deliberately not represented as executable here. A future refit needs compatible input files with stable chronological split/cutoff and target identity, approved data access, CUDA-enabled PyTorch/XGBoost/CatBoost runtime, and an exact environment lock. The plot-only lock in `figure-reconstruction/` is not the model-fit lock.

No match-level score or forecast file is present. Saved aggregate tables can be read as fixed output, but there is no row-level score archive in this bundle from which to recalculate metrics. The only runnable reconstruction command here is figure rendering from the included aggregate projections.
